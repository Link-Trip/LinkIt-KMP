## 한눈에 보기

마이페이지는 메인 지도 화면 우상단의 프로필 버튼으로 진입하는 설정성 화면이다. 사용자는 여기서 지도 표시 방식을 고르고, 기기 알림 상태를 확인해 설정으로 이동하거나 앱 알림 수신을 켜고 끄고, 서비스에 의견을 보내고, 약관을 읽고, 앱을 초기 상태로 되돌린다.

| 영역 | 항목 | 사용자가 얻는 것 |
|---|---|---|
| 알림 안내 카드 | 기기 알림이 꺼져있어요 / 설정하러 가기 | 영상 분석 완료 알림을 놓치지 않도록 기기 설정으로 바로 이동 |
| 지도 설정 | 기본 / 위성 | 앱 안 모든 지도 화면의 표시 방식 선택. 앱 초기화 전까지 유지 |
| 알림설정 | 알림 (토글) | 기기 알림 권한이 꺼져 있으면 비활성 토글과 기기 설정 이동, 켜져 있으면 앱 알림 수신을 직접 켜고 끄기 |
| 도움말 & 지원 | 의견 보내기 | 유형을 골라 의견을 작성하고 전송 (하루 최대 5회) |
| 도움말 & 지원 | 이용약관 | 서비스 이용약관, 개인정보 처리방침, 오픈소스 라이센스 고지, 위치기반 서비스 이용약관 열람 |
| 앱 설정 | 앱 초기화 | 확인 팝업 후 저장 데이터와 지도 설정을 지우고 온보딩 시작 화면으로 이동 |

## Clarifications

### Session 2026-09-18

- Q: 앱 초기화 시 디자인이 명시한 4개 데이터 외에 온보딩 완료 여부 같은 최초 진입 상태도 함께 초기화하는가? → A: 예. 저장 일정, 저장 장소, 보관함 저장항목, 지도 설정에 더해 온보딩 완료 여부와 알림 안내 노출 이력 등 최초 진입 관련 상태를 모두 초기화해 첫 설치 상태로 되돌린다.
- Q: 지도 설정(기본/위성)은 메인 지도 화면에만 적용되는가, 앱 안의 다른 지도 화면에도 적용되는가? → A: 앱 안의 모든 지도 화면(메인 지도, 일정 상세 지도, 장소 선택 지도 등)에 동일하게 적용된다.
- Q: 이용약관 4종의 본문은 앱 내장 문서인가, 서버 본문인가, 웹페이지인가? → A: 운영 측이 관리하는 웹페이지를 앱을 벗어나지 않고 앱 안에서 열어 표시한다. 운영 측이 웹에서 직접 수정하며 네트워크가 필요하다.
- Q: 의견 보내기 바텀시트를 열었을 때 유형 칩은 미선택 상태로 시작하는가, `제안`이 미리 선택되어 있는가? → A: 아무 칩도 선택되지 않은 상태로 시작한다. 선택된 칩을 다시 누르면 해제되어 미선택으로 돌아갈 수 있으며, 미선택으로 보내면 `기타`로 기록된다.
- Q: 의견 보내기 입력창의 최대 글자 수는 몇 자인가? → A: 200자. 상한에 도달하면 추가 입력이 막힌다.

### Session 2026-09-23

- Q: `알림` 토글은 기기 권한만 보여주는 읽기 전용 표시인가, 사용자가 앱 안에서 알림 수신을 켜고 끄는 설정인가? → A: 두 계층이다. 기기 알림 권한이 꺼져 있으면 토글은 비활성(disabled)·꺼짐으로 표시하고 설정으로 이동하는 안내 UI를 보여준다. 권한이 켜져 있으면 토글은 활성(enabled)이며 앱 알림 수신 설정에 따라 켜짐/꺼짐을 표시하고, 안내 UI는 보이지 않는다.
- Q: 알림 수신 설정은 어디에 저장하고 서비스에는 어떻게 반영하는가? → A: 앱 로컬에 저장하고(기본값 켜짐), 사용자가 토글을 바꿀 때 서비스 `PUT /members/me/notification`으로 반영한다. 서비스에 조회 API가 없으므로 로컬 값이 표시의 기준이다. 반영에 실패하면 토글을 되돌리고 실패를 알린다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 마이페이지 진입과 지도 설정 변경 (Priority: P1)

사용자는 메인 지도 화면 우상단의 프로필 버튼을 눌러 마이페이지에 들어온다. `지도 설정` 아래 `기본`과 `위성` 미리보기 카드 중 하나를 선택하면 즉시 선택 상태가 바뀌고, 변경 안내 토스트가 뜨며, 메인 지도를 비롯한 앱 안의 모든 지도 화면 표시 방식이 그에 맞게 바뀐다. 앱을 종료했다가 다시 열어도 마지막 선택이 유지된다.

**Why this priority**: 마이페이지의 진입 경로이자, 메인 지도 경험에 직접 영향을 주는 유일한 설정이다. 이 스토리만 구현해도 사용자는 지도 표시 방식을 바꿀 수 있어 독립적인 가치가 있다.

**Independent Test**: 메인 지도에서 프로필 버튼을 눌러 마이페이지에 진입하고 `위성`을 선택한 뒤 메인 지도로 돌아가 위성 표시를 확인하고, 앱 재실행 후에도 `위성`이 선택되어 있는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 메인 지도 화면이 표시된 상태, **When** 우상단 프로필 버튼을 누르면, **Then** 상단에 뒤로가기와 `마이페이지` 제목이 있는 마이페이지 화면이 열린다.
2. **Given** 지도 설정을 한 번도 바꾼 적 없는 사용자가 마이페이지에 진입한 상태, **When** 화면을 보면, **Then** `기본` 카드가 선택 상태로 표시된다.
3. **Given** `기본`이 선택된 상태, **When** `위성` 카드를 누르면, **Then** `위성`이 선택 상태가 되고 하단에 `위성 지도로 변경되었습니다.` 토스트가 표시된다.
4. **Given** `위성`이 선택된 상태, **When** `기본` 카드를 누르면, **Then** `기본`이 선택 상태가 되고 `기본 지도로 변경되었습니다.` 토스트가 표시된다.
5. **Given** `위성`을 선택한 상태, **When** 뒤로가기로 메인 지도 화면에 돌아가면, **Then** 지도가 위성 표시 방식으로 그려진다.
6. **Given** `위성`을 선택한 상태, **When** 일정 상세 등 지도가 있는 다른 화면을 열면, **Then** 그 화면의 지도도 위성 표시 방식으로 그려진다.
7. **Given** `위성`을 선택한 상태, **When** 앱을 완전히 종료한 뒤 다시 실행하면, **Then** 메인 지도는 위성 표시이고 마이페이지에서도 `위성`이 선택 상태다.
8. **Given** 이미 선택된 카드가 있는 상태, **When** 같은 카드를 다시 누르면, **Then** 선택 상태는 그대로이고 변경 토스트는 표시되지 않는다.

### User Story 2 - 앱 초기화 (Priority: P1)

사용자는 `앱 설정` 아래 `앱 초기화`를 눌러 확인 팝업을 본다. `초기화`를 선택하면 저장 일정, 저장 장소, 보관함 저장항목, 지도 설정이 모두 지워지고 앱은 온보딩 시작 화면으로 이동하며 완료 토스트가 표시된다. `돌아가기`나 닫기를 선택하면 아무것도 바뀌지 않는다.

**Why this priority**: 되돌릴 수 없는 파괴적 동작이므로 확인 흐름과 삭제 범위가 정확해야 한다. 사이트맵에서도 프로필 페이지의 핵심 액션으로 정의되어 있다.

**Independent Test**: 저장 일정과 보관함 항목이 있는 상태에서 앱 초기화를 실행하고, 온보딩 시작 화면 진입과 완료 토스트를 확인한 뒤 온보딩을 마치고 메인 지도에 저장 일정이 0건이고 지도 설정이 `기본`인지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 마이페이지가 표시된 상태, **When** `앱 초기화`를 누르면, **Then** `정말 앱을 초기화 하시겠어요?` 제목과 `앱을 초기화하면 다시 복구할 수 없어요` 설명, `초기화`(강조) 버튼, `돌아가기` 버튼, 닫기 아이콘이 있는 확인 팝업이 마이페이지 위에 표시된다.
2. **Given** 초기화 확인 팝업이 표시된 상태, **When** `돌아가기` 또는 닫기 아이콘을 누르면, **Then** 팝업이 닫히고 마이페이지가 그대로 유지되며 어떤 데이터도 삭제되지 않는다.
3. **Given** 저장 일정 3건, 저장 장소 2건, 보관함 저장항목 1건, 지도 설정 `위성`인 상태에서 팝업이 표시된 상태, **When** `초기화`를 누르면, **Then** 앱은 온보딩 시작 화면으로 이동하고 하단에 `앱 초기화가 완료되었습니다.` 토스트가 표시된다.
4. **Given** 초기화가 완료된 상태, **When** 온보딩을 마치고 메인 지도에 진입하면, **Then** 저장 일정과 저장 장소, 보관함 저장항목은 0건이고 지도 설정은 `기본`이다.
5. **Given** 초기화가 완료된 상태, **When** 뒤로가기를 누르면, **Then** 마이페이지나 이전 메인 지도 화면으로 돌아가지 않는다.
6. **Given** 초기화 완료 후 온보딩을 마치지 않고 앱을 종료한 상태, **When** 앱을 다시 실행하면, **Then** 첫 설치 때와 같이 온보딩 시작 화면부터 표시된다.

### User Story 3 - 의견 보내기 (Priority: P2)

사용자는 `도움말 & 지원` 아래 `의견 보내기`를 눌러 바텀시트를 연다. 안내 문구를 읽고 `제안`, `오류·버그`, `기타` 중 유형을 하나 고른 뒤 내용을 입력하고 `보내기`를 누른다. 전송이 성공하면 바텀시트가 닫히고 완료 토스트가 뜬다. 하루 5회를 초과했거나 네트워크 오류가 나면 각각 다른 토스트로 알린다.

**Why this priority**: 서비스 개선 채널로 중요하지만 핵심 여행 일정 경험에는 직접 영향을 주지 않는다. 전송 성공·초과·실패 세 결과를 모두 다뤄야 완결된다.

**Independent Test**: 마이페이지에서 `의견 보내기`를 열고 유형 선택 없이 1자 이상 입력한 뒤 전송해 완료 토스트를 확인하고, 같은 날 6번째 전송에서 초과 토스트를, 네트워크 차단 상태 전송에서 실패 토스트를 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 마이페이지가 표시된 상태, **When** `의견 보내기`를 누르면, **Then** 닫기 아이콘, `의견 보내기` 제목, 안내 문구(`보내주신 의견은 서비스 개선에 활용돼요. (개별 답변은 어려워요 🥹) 스팸 방지를 위해 하루 최대 5회까지 전송할 수 있어요!`), 아무것도 선택되지 않은 유형 칩 3개(`제안`, `오류·버그`, `기타`), 입력창(플레이스홀더 `핑고를 쓰면서 느낀 점이나 발견한 문제를 알려주세요!`), 비활성 `보내기` 버튼이 있는 바텀시트가 열린다.
2. **Given** 바텀시트가 열린 상태, **When** 유형 칩 하나를 누르면, **Then** 그 칩만 선택 상태가 되고 이미 선택된 다른 칩은 해제된다. 선택된 칩을 다시 누르면 해제되어 미선택 상태로 돌아간다.
3. **Given** 입력창이 비어 있는 상태, **When** 1자 이상 입력하면, **Then** `보내기` 버튼이 활성화된다. 내용을 모두 지우면 다시 비활성화된다.
4. **Given** 입력창에 200자를 입력한 상태, **When** 글자를 더 입력하거나 붙여넣으면, **Then** 200자를 넘는 부분은 입력되지 않고 기존 200자만 유지된다.
5. **Given** 유형을 고르지 않고 내용을 입력한 상태, **When** `보내기`를 누르면, **Then** 의견은 유형 `기타`로 전송된다.
6. **Given** 내용을 입력한 상태, **When** `보내기`를 누르고 전송이 성공하면, **Then** 앱 버전, 운영체제, 기기 정보가 의견과 함께 전달되고 바텀시트가 닫히며 `의견 전송이 완료되었습니다.` 토스트가 표시된다.
7. **Given** 같은 날 이미 5회 전송한 상태, **When** `보내기`를 누르면, **Then** 서비스가 전송을 거부하고 `최대 의견 전송 횟수를 초과했습니다.` 토스트가 표시된다.
8. **Given** 네트워크가 끊긴 상태, **When** `보내기`를 누르면, **Then** `전송에 실패했습니다. 다시 시도해주세요.` 토스트가 표시되고 바텀시트와 입력 내용은 유지되어 재시도할 수 있다.
9. **Given** 내용을 입력한 상태, **When** 닫기 아이콘을 누르거나 시트 밖을 눌러 닫으면, **Then** 바텀시트가 닫히고 아무것도 전송되지 않는다.

### User Story 4 - 알림 상태 확인과 기기 알림 설정 이동 (Priority: P2)

사용자는 마이페이지에서 기기 알림 권한이 허용되어 있는지, 그리고 앱 알림을 받고 있는지 한눈에 본다. 기기 권한이 꺼져 있으면 화면 최상단에 안내 카드가 뜨고 `알림` 토글은 비활성(disabled)·꺼짐으로 표시된다. 카드의 `설정하러 가기`나 `알림` 항목을 누르면 기기의 앱 알림 설정 화면으로 이동하고, 돌아오면 바뀐 상태가 반영된다. 기기 권한이 켜져 있으면 안내 카드는 사라지고 토글이 활성(enabled)되어 앱 알림 수신 설정에 따라 켜짐/꺼짐을 표시하며, 토글을 눌러 수신을 켜고 끌 수 있다.

**Why this priority**: 영상 분석 완료 알림을 놓치는 문제를 줄이는 보조 기능이다. 기기 권한은 OS가 결정하므로 앱은 상태 표시와 설정 이동을 담당하고, 권한이 있을 때는 사용자가 앱 안에서 수신 여부를 정할 수 있게 한다.

**Independent Test**: 기기 알림을 끈 상태에서 마이페이지에 진입해 안내 카드와 비활성·꺼진 토글을 확인하고, `설정하러 가기`로 기기 설정에 가서 알림을 켠 뒤 돌아왔을 때 카드가 사라지고 토글이 활성·켜짐이 되는지 확인한다. 이어서 토글을 눌러 꺼짐으로 바꾸고 앱을 재실행해도 꺼짐이 유지되는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 기기에서 이 앱의 알림 권한이 꺼져 있는 상태, **When** 마이페이지에 진입하면, **Then** 최상단에 `기기 알림이 꺼져있어요` 제목, `알림이 꺼져있으면 영상 분석이 완료되어도 바로 알 수 없어요!` 설명, `설정하러 가기` 버튼이 있는 안내 카드가 표시되고 `알림` 토글은 비활성(disabled)·꺼진 상태로 표시된다. 이때 앱 알림 수신 설정값과 무관하게 항상 꺼짐으로 보인다.
2. **Given** 기기 알림 권한이 켜져 있고 앱 알림 수신 설정이 켜짐인 상태, **When** 마이페이지에 진입하면, **Then** 안내 카드는 표시되지 않고 `알림` 토글은 활성(enabled)·켜진 상태로 표시되며 `지도 설정`이 첫 항목으로 보인다.
3. **Given** 기기 알림 권한이 켜져 있고 앱 알림 수신 설정이 꺼짐인 상태, **When** 마이페이지에 진입하면, **Then** 안내 카드는 표시되지 않고 `알림` 토글은 활성·꺼진 상태로 표시된다.
4. **Given** 기기 알림 권한이 꺼진 상태, **When** `설정하러 가기` 또는 `알림` 항목(토글 포함)을 누르면, **Then** 기기의 이 앱 알림 설정 화면으로 이동한다.
5. **Given** 기기 알림 설정 화면에서 권한을 켠 상태, **When** 앱으로 돌아오면, **Then** 안내 카드가 사라지고 토글이 활성되어 앱 알림 수신 설정값(켜짐/꺼짐)으로 갱신된다.
6. **Given** 기기 알림 설정 화면에서 권한을 끈 상태, **When** 앱으로 돌아오면, **Then** 안내 카드가 표시되고 토글이 비활성·꺼진 상태로 갱신된다.
7. **Given** 기기 알림 권한이 켜져 있고 토글이 켜진 상태, **When** `알림` 항목 또는 토글을 누르면, **Then** 토글이 즉시 꺼짐으로 바뀌고 서비스에 수신 꺼짐이 반영되며, 앱을 재실행해도 꺼짐이 유지된다. 다시 누르면 같은 방식으로 켜짐이 된다.
8. **Given** 기기 알림 권한이 켜져 있고 네트워크가 끊긴 상태, **When** 토글을 누르면, **Then** 토글이 원래 상태로 되돌아가고 `알림 설정 변경에 실패했습니다. 다시 시도해주세요.` 토스트가 표시된다.

### User Story 5 - 이용약관 열람 (Priority: P3)

사용자는 `도움말 & 지원` 아래 `이용약관`을 눌러 약관 목록을 본다. `서비스 이용약관`, `개인정보 처리방침`, `오픈소스 라이센스 고지`, `위치기반 서비스 이용약관` 중 하나를 누르면 해당 약관 웹페이지가 앱 안에서 열리고, 본문을 끝까지 스크롤해 읽을 수 있다. 네트워크가 없으면 안내와 재시도 수단이 보인다.

**Why this priority**: 배포 전 필수 고지 사항이지만 사용 빈도가 낮고 다른 기능에 영향을 주지 않는다.

**Independent Test**: `이용약관`을 눌러 4개 항목이 보이는지, 각 항목을 눌러 해당 약관 웹페이지가 앱 안에서 열리고 뒤로가기로 목록으로 돌아오는지, 네트워크를 끊고 열었을 때 안내와 재시도가 보이는지 확인하면 검증된다.

**Acceptance Scenarios**:

1. **Given** 마이페이지가 표시된 상태, **When** `이용약관`을 누르면, **Then** 뒤로가기와 `이용약관` 제목이 있는 목록 화면에 `서비스 이용약관`, `개인정보 처리방침`, `오픈소스 라이센스 고지`, `위치기반 서비스 이용약관` 4개 항목이 순서대로 표시된다.
2. **Given** 약관 목록이 표시된 상태에서 네트워크가 연결된 상태, **When** 항목 하나를 누르면, **Then** 상단에 뒤로가기와 해당 약관 제목이 있는 상세 화면이 열리고, 그 안에 해당 약관 웹페이지가 표시된다. 웹페이지가 뜨기 전까지는 로딩 중임이 보인다.
3. **Given** 약관 상세가 표시된 상태, **When** 본문을 스크롤하면, **Then** 문서 제목, 조항 소제목, 본문이 위계가 구분되는 서식으로 끝까지 읽힌다.
4. **Given** 약관 상세가 표시된 상태, **When** 뒤로가기를 누르면, **Then** 약관 목록으로 돌아가고, 목록에서 뒤로가기를 누르면 마이페이지로 돌아간다.
5. **Given** 네트워크가 끊긴 상태, **When** 약관 항목 하나를 누르면, **Then** 빈 화면 대신 불러오지 못했다는 안내와 `다시 시도` 수단이 보이고, 네트워크가 복구된 뒤 다시 시도하면 웹페이지가 표시된다.
6. **Given** 약관 웹페이지가 표시된 상태, **When** 본문 안의 다른 링크를 누르면, **Then** 앱을 벗어나지 않고 같은 상세 화면 안에서 열리거나, 외부 링크라면 기기 브라우저로 열린다.

### Edge Cases

- 지도 설정 변경 토스트가 아직 떠 있는 동안 다른 카드를 다시 누르면 토스트 문구는 마지막 선택을 기준으로 갱신되고 하나만 표시된다.
- 의견 보내기 바텀시트가 열린 채 앱이 백그라운드로 갔다가 돌아와도 선택한 유형과 입력 내용은 유지된다.
- 의견 전송 중에 `보내기`를 연속으로 누르면 한 번만 전송되고, 전송이 끝날 때까지 버튼은 다시 누를 수 없다.
- 의견 내용이 공백만으로 이루어진 경우 `보내기`는 활성화되지 않는다.
- 200자를 넘는 텍스트를 붙여넣으면 앞에서부터 200자까지만 남는다.
- 초기화 확인 팝업에서 `초기화`를 누른 뒤 삭제가 완료되기 전에는 팝업을 닫거나 다시 누를 수 없어야 하며, 삭제가 끝난 뒤에만 온보딩으로 이동한다.
- 앱 초기화 도중 앱이 강제 종료되면 다음 실행 시 저장 데이터가 일부만 남은 상태가 되어선 안 된다. 삭제가 완료되지 않았다면 초기화 전 상태로 남거나, 다음 실행 시 나머지 삭제가 마무리되어야 한다.
- 기기 알림 설정 화면을 열 수 없는 환경(설정 화면 이동이 지원되지 않는 기기)에서는 마이페이지에 그대로 머물고 오류 없이 상태 표시만 유지된다.
- 약관 웹페이지가 아직 준비되지 않았거나 주소가 잘못되어 열리지 않는 항목은 목록에는 표시되되 상세 화면에서 불러오지 못했다는 안내가 보인다.
- 약관 웹페이지 로딩이 오래 걸릴 때(수 초 이상) 사용자는 뒤로가기로 언제든 목록으로 돌아갈 수 있다.
- 마이페이지 진입 시 기기 알림 권한을 읽지 못하면 안내 카드는 숨기고 토글은 비활성·꺼진 상태로 표시한다.
- 알림 수신 설정을 서비스에 반영하는 중에 토글을 다시 누르면 무시되고, 반영이 끝난 뒤에만 다시 바꿀 수 있다.
- 앱 알림 수신 설정이 꺼진 상태에서 기기 권한을 껐다가 다시 켜도 수신 설정은 꺼짐으로 유지된다. 권한 변화는 수신 설정을 바꾸지 않는다.
- 서비스에 알림 수신 설정을 조회하는 수단이 없으므로, 재설치·기기 변경·앱 초기화 후에는 수신 설정이 기본값(켜짐)에서 시작하고 서비스 값과 다를 수 있다. 다음 토글 조작 시 서비스 값이 앱 값으로 맞춰진다.

## Requirements *(mandatory)*

### Functional Requirements

**진입과 구조**

- **FR-001**: 메인 지도 화면 우상단 프로필 버튼을 누르면 마이페이지 화면이 열려야 한다.
- **FR-002**: 마이페이지 상단에는 뒤로가기와 `마이페이지` 제목이 있어야 하며, 뒤로가기는 메인 지도 화면으로 돌아가야 한다.
- **FR-003**: 마이페이지 본문은 `알림 안내 카드(조건부)`, `지도 설정`, `알림설정`, `도움말 & 지원`(의견 보내기, 이용약관), `앱 설정`(앱 초기화) 순서로 구성되어야 한다.

**지도 설정**

- **FR-004**: `지도 설정`은 `기본`과 `위성` 두 옵션을 미리보기 카드로 제공하고 항상 정확히 하나만 선택 상태여야 한다.
- **FR-005**: 지도 설정을 한 번도 변경하지 않은 사용자에게는 `기본`이 선택되어 있어야 한다.
- **FR-006**: 선택되지 않은 카드를 누르면 즉시 선택이 바뀌고 `위성 지도로 변경되었습니다.` 또는 `기본 지도로 변경되었습니다.` 토스트가 표시되어야 한다. 이미 선택된 카드를 누르면 아무 변화가 없어야 한다.
- **FR-007**: 선택한 지도 설정은 메인 지도를 포함해 앱 안의 모든 지도 화면(일정 상세 지도, 장소 선택 지도 등)의 표시 방식에 동일하게 반영되어야 하며, 앱을 종료하고 다시 실행해도 유지되어야 한다. 이 값은 앱 초기화 때만 `기본`으로 되돌아간다.

**알림 안내 카드와 알림설정**

- **FR-008**: 기기에서 이 앱의 알림 권한이 꺼져 있을 때만 마이페이지 최상단에 `기기 알림이 꺼져있어요` 안내 카드를 표시해야 한다. 카드에는 설명 문구 `알림이 꺼져있으면 영상 분석이 완료되어도 바로 알 수 없어요!`와 `설정하러 가기` 버튼이 있어야 한다. 권한이 켜져 있으면 카드를 표시하지 않아야 한다.
- **FR-009**: 기기 알림 권한이 꺼져 있거나 읽을 수 없으면 `알림설정`의 `알림` 토글은 비활성(disabled)·꺼짐으로 표시되어야 하며, 앱 알림 수신 설정값과 무관하게 항상 꺼짐으로 보여야 한다.
- **FR-010**: `설정하러 가기` 버튼을 누르거나, 기기 알림 권한이 꺼진 상태에서 `알림` 항목(토글 포함)을 누르면 기기의 이 앱 알림 설정 화면으로 이동해야 한다.
- **FR-011**: 기기 알림 설정 화면에서 앱으로 돌아오면 안내 카드 표시 여부와 토글의 활성 여부·켜짐 상태가 최신 기기 권한과 앱 알림 수신 설정으로 갱신되어야 한다.
- **FR-011a**: 기기 알림 권한이 켜져 있으면 `알림` 토글은 활성(enabled)이어야 하며, 앱 알림 수신 설정이 켜짐이면 켜진 모양, 꺼짐이면 꺼진 모양으로 표시되어야 한다.
- **FR-011b**: 기기 알림 권한이 켜진 상태에서 `알림` 항목 또는 토글을 누르면 앱 알림 수신 설정이 반대 값으로 바뀌어 즉시 토글에 반영되고, 서비스에 그 값이 반영되어야 한다. 반영이 끝나기 전에는 다시 누를 수 없어야 한다. 성공하면 앱을 종료하고 다시 실행해도 유지되어야 한다.
- **FR-011c**: 서비스 반영에 실패하면 토글을 누르기 전 값으로 되돌리고 `알림 설정 변경에 실패했습니다. 다시 시도해주세요.` 토스트를 표시해야 한다.
- **FR-011d**: 앱 알림 수신 설정의 기본값은 켜짐이며, 앱 초기화 때 기본값으로 되돌아가야 한다. 기기 권한의 변화만으로는 서비스에 알림 설정을 보내지 않아야 한다.

**의견 보내기**

- **FR-012**: `의견 보내기`를 누르면 마이페이지 위로 바텀시트가 열려야 한다. 바텀시트에는 닫기 아이콘, `의견 보내기` 제목, 안내 문구, 유형 칩(`제안`, `오류·버그`, `기타`), 여러 줄 입력창, `보내기` 버튼이 있어야 한다.
- **FR-013**: 유형 칩은 바텀시트를 열 때 아무것도 선택되지 않은 상태로 시작하는 단일 선택이어야 한다. 하나를 선택하면 다른 선택은 해제되고, 선택된 칩을 다시 누르면 해제되어 미선택으로 돌아가며, 미선택 상태로 전송하면 유형은 `기타`로 기록되어야 한다.
- **FR-014**: `보내기` 버튼은 공백을 제외한 내용이 1자 이상일 때만 활성화되어야 한다. 입력 내용은 최대 200자로 제한되며, 상한에 도달하면 추가 입력이 막혀야 한다.
- **FR-015**: 전송 시 사용자가 입력한 유형과 내용에 더해 앱 버전, 운영체제, 기기 정보가 자동으로 함께 전달되어야 하며, 이 사실은 바텀시트 안내 문구로 사용자에게 고지되어야 한다.
- **FR-016**: 의견 전송은 하루 최대 5회로 제한된다. 제한 안내는 바텀시트 문구로 사전에 제공하고, 실제 차단은 서비스 측에서 수행해야 한다. 6회째 전송 시도는 거부되고 `최대 의견 전송 횟수를 초과했습니다.` 토스트가 표시되어야 한다.
- **FR-017**: 전송이 성공하면 바텀시트가 닫히고 `의견 전송이 완료되었습니다.` 토스트가 표시되어야 한다.
- **FR-018**: 네트워크 오류 등으로 전송이 실패하면 `전송에 실패했습니다. 다시 시도해주세요.` 토스트를 표시하고 바텀시트와 입력 내용을 유지해 재시도할 수 있어야 한다.
- **FR-019**: 전송이 진행되는 동안 `보내기` 버튼은 중복으로 눌리지 않아야 한다.

**이용약관**

- **FR-020**: `이용약관`을 누르면 `서비스 이용약관`, `개인정보 처리방침`, `오픈소스 라이센스 고지`, `위치기반 서비스 이용약관` 4개 항목이 있는 목록 화면이 열려야 한다.
- **FR-021**: 각 항목을 누르면 상단에 뒤로가기와 해당 약관 제목이 있는 상세 화면이 열리고, 그 안에 운영 측이 관리하는 해당 약관 웹페이지가 앱을 벗어나지 않고 표시되어야 한다. 웹페이지 본문은 문서 제목, 조항 소제목, 본문 세 단계의 서식으로 구분되어야 한다.
- **FR-021a**: 웹페이지를 불러오는 동안 로딩 중임을 표시해야 하며, 네트워크 오류 등으로 불러오지 못하면 빈 화면 대신 안내 문구와 `다시 시도` 수단을 보여야 한다.
- **FR-021b**: 약관 4종 각각의 웹페이지 주소는 운영 측이 정해 제공하며, 약관 개정은 웹페이지 수정만으로 반영되어 앱 업데이트를 요구하지 않아야 한다.
- **FR-022**: 약관 상세와 목록에서 뒤로가기는 각각 목록과 마이페이지로 돌아가야 한다.

**앱 초기화**

- **FR-023**: `앱 초기화`를 누르면 즉시 실행하지 않고 `정말 앱을 초기화 하시겠어요?` 제목, `앱을 초기화하면 다시 복구할 수 없어요` 설명, `초기화` 버튼(강조), `돌아가기` 버튼, 닫기 아이콘이 있는 확인 팝업을 표시해야 한다.
- **FR-024**: `돌아가기` 또는 닫기 아이콘을 누르면 팝업만 닫히고 어떤 데이터도 변경되지 않아야 한다.
- **FR-025**: `초기화`를 누르면 저장 일정, 저장 장소, 보관함 저장항목, 지도 설정을 모두 삭제하거나 기본값으로 되돌려야 하며, 온보딩 완료 여부와 알림 안내 노출 이력 등 최초 진입 관련 상태도 첫 설치 상태로 되돌려야 한다.
- **FR-026**: 초기화가 완료되면 앱은 온보딩 시작 화면으로 이동하고 `앱 초기화가 완료되었습니다.` 토스트를 표시해야 하며, 뒤로가기로 이전 마이페이지나 메인 지도 화면으로 되돌아갈 수 없어야 한다.
- **FR-027**: 초기화는 원자적으로 완료되어야 한다. 도중에 중단되더라도 저장 데이터가 일부만 남은 상태로 사용자에게 노출되어선 안 된다.

### Key Entities

- **지도 표시 설정 (Map Display Preference)**: 사용자가 고른 지도 표시 방식. 값은 `기본` 또는 `위성`이며 기본값은 `기본`. 앱 전체에서 하나만 존재해 모든 지도 화면이 공유하고, 앱 초기화 때 기본값으로 돌아간다.
- **의견 (Feedback)**: 사용자가 보낸 한 건의 의견. 유형(`제안`, `오류·버그`, `기타`), 내용, 전송 시각과 함께 앱 버전, 운영체제, 기기 정보가 자동으로 붙는다. 하루 전송 횟수 제한의 집계 단위다.
- **약관 문서 (Terms Document)**: 열람 가능한 고지 문서. 종류(서비스 이용약관, 개인정보 처리방침, 오픈소스 라이센스 고지, 위치기반 서비스 이용약관), 앱에 표시할 제목, 운영 측이 관리하는 웹페이지 주소를 가진다. 본문과 시행일은 웹페이지가 담는다.
- **초기화 대상 데이터 (Resettable App Data)**: 앱 초기화가 지우는 데이터 묶음. 사용자 데이터인 저장 일정, 저장 장소, 보관함 저장항목, 지도 표시 설정, 앱 알림 수신 설정과, 최초 진입 상태인 온보딩 완료 여부·알림 안내 노출 이력으로 구성된다.
- **기기 알림 상태 (Device Notification Status)**: 기기가 이 앱의 알림을 허용하는지 여부. 앱이 저장하지 않고 진입·복귀 시마다 기기에서 읽는다. 토글의 활성 여부와 안내 카드 표시 여부를 결정한다.
- **앱 알림 수신 설정 (Notification Receive Preference)**: 사용자가 앱 안에서 정한 푸시 알림 수신 여부. 기본값은 켜짐. 앱 로컬에 저장하고 변경 시 서비스에 반영한다. 기기 권한이 켜져 있을 때 토글의 켜짐/꺼짐을 결정하며, 앱 초기화 때 기본값으로 돌아간다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 지도 설정 카드를 누른 뒤 1초 이내에 선택 상태와 토스트가 바뀌고, 메인 지도와 그 밖의 모든 지도 화면이 100% 선택한 방식으로 표시된다.
- **SC-002**: 지도 설정을 바꾼 뒤 앱을 재실행한 100회 시도에서 마지막 선택이 매번 유지된다.
- **SC-003**: 처음 사용하는 사용자가 마이페이지 진입부터 의견 전송 완료까지 별도 안내 없이 1분 이내에 마칠 수 있다.
- **SC-004**: 같은 날 6회째 이후의 의견 전송 시도는 0건이 서비스에 기록되고, 매번 초과 토스트가 표시된다.
- **SC-005**: 앱 초기화 후 저장 일정, 저장 장소, 보관함 저장항목이 0건이고 지도 설정이 `기본`이며 온보딩 시작 화면이 표시되는 비율이 100%다.
- **SC-006**: 기기 알림 설정을 바꾸고 앱으로 돌아왔을 때 안내 카드와 토글의 활성 여부·켜짐 상태가 2초 이내에 실제 기기 권한과 앱 알림 수신 설정에 일치한다.
- **SC-009**: 기기 권한이 켜진 상태에서 토글을 누른 뒤 1초 이내에 토글 모양이 바뀌고, 네트워크가 연결된 상태에서는 서비스에 기록된 알림 수신 여부가 100% 토글과 일치한다. 앱 재실행 100회 시도에서 마지막 토글 값이 매번 유지된다.
- **SC-007**: 마이페이지에서 4종 약관 중 어느 것이든 2번의 탭으로 도달할 수 있고, 일반적인 이동통신망에서 항목을 누른 뒤 3초 이내에 약관 웹페이지가 읽을 수 있는 상태로 표시된다.
- **SC-008**: 초기화 확인 팝업에서 `돌아가기`를 선택한 경우 데이터가 변경된 사례가 0건이다.

## Assumptions

- **진입 경로**: 마이페이지는 하단 탭이 아니라 메인 지도 화면 우상단 프로필 버튼으로만 진입한다. Figma 유저플로우와 사이트맵의 `프로필 페이지`가 이 화면이다.
- **로그인 없음**: 앱에 계정 개념이 없으므로 의견 전송 횟수 제한은 기기 단위로 집계하며, "하루"의 경계는 서비스 측 기준일을 따른다.
- **의견 유형 시안 표시**: 디자인 시안에서 `제안` 칩이 강조된 것은 선택 상태의 예시이며 초기 상태가 아니다. 초기 상태는 Clarifications에서 미선택으로 확정했다.
- **의견 내용 길이 표시**: 상한은 Clarifications에서 200자로 확정했다. 디자인에 글자 수 표시가 없으므로 남은 글자 수 카운터는 표시하지 않는다.
- **알림 토글의 의미**: 토글은 두 계층을 합쳐 보여준다. 기기 알림 권한(OS 설정)이 토글의 활성 여부와 안내 카드 표시를 정하고, 앱 알림 수신 설정(사용자가 앱 안에서 정하는 값)이 권한이 있을 때의 켜짐/꺼짐을 정한다. 디자인 설명의 "선택 시 디바이스 알림 설정 화면으로 이탈"은 권한이 꺼진 상태에만 적용한다(2026-09-23 Clarification).
- **알림 수신 설정의 기준값**: 서비스에는 알림 수신 설정을 바꾸는 API만 있고 조회 API가 없으므로, 앱 로컬 저장값을 표시 기준으로 삼고 변경 때마다 서비스에 반영한다. 조회 API가 생기면 진입 시 로컬 값을 서비스 값으로 맞춘다(`docs/specs/mypage-screen.md` TBD-06).
- **초기화 후 온보딩**: 초기화 완료 후 온보딩 시작 화면(`여행 영상, 이제 저장만 하지 마세요` 배지, 서비스 후킹 문구, `30초 만에 사용법 보기`·`바로 시작하기` 버튼 — 002 시안 문구)으로 이동한다. 초기화 범위는 Clarifications에서 확정한 대로 사용자 데이터 4종과 최초 진입 상태를 모두 포함한다. 단, 캐시나 최근 검색어처럼 위 목록에 없는 로컬 값까지 예외 없이 지우는 것은 요구하지 않는다.
- **약관 본문 출처**: Figma의 약관 본문은 `(예시)` 표기가 있는 자리 표시 문서다. 실제 본문(운영 주체 명칭 `핑고 운영팀`, 문의 이메일, 개인정보 보유기간, 시행일, 오픈소스 라이선스 전체 목록 등)은 Figma 메모 `게시 전 필수` 항목대로 운영 측이 확정해 웹페이지로 게시한다. 앱은 그 웹페이지를 앱 안에서 열어 보여주며, 이 스펙은 본문 내용이 아니라 열람 화면과 실패 처리를 정의한다.
- **약관 웹페이지 주소**: 4종 약관의 웹페이지 주소는 운영 측이 제공하며, 주소가 확정되기 전까지는 자리 표시 주소로 화면 흐름을 검증한다. 웹페이지의 서식(문서 제목, 조항 소제목, 본문)은 Figma 텍스트 가이드를 따르되 운영 측 웹페이지가 책임진다.
- **기존 구현과의 차이**: 현재 앱에는 이전 디자인 기준의 마이페이지(피드백 보내기·버그 신고하기 2개 항목, 알림설정 없음, 초기화 팝업 버튼 문구 `이전으로 돌아가기`)가 있다. 이 스펙의 Figma(2026-03-12)가 최신이며, 기존 `docs/specs/mypage-screen.md`(v0.1.2, 이전 노드 기준)의 TBD-01~03은 이 스펙에서 모두 결론이 났다.
- **의존성**: 의견 전송과 횟수 제한 차단은 서비스 측 처리를 전제로 한다. 저장 일정·장소·보관함 데이터는 각각 지도, 일정, 보관함 기능이 관리하며, 초기화는 그 데이터를 지우는 요청을 통합해 수행한다.
- **초기화 후 사용자 식별**: 서비스 측은 앱 초기화를 사용자 탈퇴로 처리한다. 초기화 뒤 같은 기기로 다시 시작하면 새 사용자로 취급되므로 의견 전송 일일 횟수 등 사용자 단위 집계도 함께 초기화된다. 되돌릴 수 없으며, 이는 초기화 팝업 문구(`앱을 초기화하면 다시 복구할 수 없어요`)와 일치한다.
